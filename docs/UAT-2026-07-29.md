## 發現

### F-1 · 中 · `employee_roster` 完全冇 grant 俾 `authenticated`
連 admin 都 `permission denied for table employee_roster`。目前前端只讀 `profiles`（[live-auth.js:49](../live-auth.js:49)），admin「員工」畫面仍用 mock data，所以未爆。但一接真數據就會即時掛。`onboarding_invites` 同樣冇 grant —— 嗰個係**刻意**嘅（只經 security-definer RPC 存取），roster 則似遺漏。

### F-2 · 中 · 啟用失敗訊息誤導用戶
[live-auth.js:144](../live-auth.js:144) 把「token 無效」同「電話格式錯」合併成一個條件：

```js
if (!email || !ONBOARDING_TOKEN.test(token)) {
  showMessage("#activation-message", "啟用連結無效，請向 Lisa 索取新的 QR code。");
```

實測：token 完全有效、只係電話打錯 `1234`，一樣叫用戶去搵 Lisa 攞新 QR。應拆成兩個訊息。

### F-3 · 低 · 登入頁空白檢查係死碼
`#login-id` 同 `#password` 都有 `required` 且 form 冇 `novalidate`，瀏覽器 native 驗證先攔截，所以 [live-auth.js:112-115](../live-auth.js:112) 嘅「請輸入電話號碼及密碼。」永遠行唔到。

### F-4 · 低 · `profiles` / `attendance_records` 對 anon 只靠 RLS 擋
其餘表都做咗 table-level `revoke`，呢兩張冇，純靠 RLS 過濾（實測回 0 行，安全）。加 revoke 會多一層縱深防禦。
